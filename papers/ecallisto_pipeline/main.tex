\begin{abstract}
A workflow scheduler is warranted on an archive that is large and frequently updated, not on a
single static catalogue, where a scheduler is overhead. The e-Callisto network \citep{benz2009} is the former: 150+ ground
stations append new gzipped-FITS dynamic spectra every day, twenty years deep. We present a small
Apache Airflow \citep{airflow} pipeline, running on rootless Podman \citep{podman}, that ingests
the archive day by day. It uses a daily schedule with catchup backfill over an arbitrary date
range, a directory sensor that waits for each day to populate, and a per-station
dynamic-task-mapping fan-out, and scans each spectrum for drifting type III candidates by reusing
a tested dynamic-spectrum toolkit. The per-station scan and the day-reduce are in-process calls
into the same \code{jansky\_research} worker that the command line uses (both paths call one shared \code{scan\_file}), so the DAG and \code{make ecallisto-day} produce the same scan
rows (the DAG additionally stamps the date and JSON-sanitises NaNs, and its per-day fan-out is
capped by default); the worker is unit-tested offline while the scheduler stack is exercised
separately. e-Callisto is uncalibrated and RFI-heavy, so a single
station's detections are candidates, not events; we vet them by cross-station coincidence, since a
real solar burst is seen at the same universal time by every sunlit station while RFI and local
artefacts are single-station. On a synthetic day (a real burst at \ecSynMaxEventStations\ stations
plus time-offset interference and morphology contaminants), the coincidence step confirms exactly
\ecSynNevents\ event and rejects everything else, in \ecSynEnsOk\ of \ecSynEnsN\ independent
seeds. On the one real archive day run end to end (2011-09-14), \ecRealNscanned\ of
\ecRealNfilesListed\ listed 15-minute spectra from \ecRealNstationsScanned\ stations were
scanned and only \ecRealNcandStations\ stations produced a type III candidate (one of them the known 11:50~UT burst) hours apart, so the coincidence step has yet to confirm a real
event on real data: the null measures single-station detection sensitivity, not the QC. The contribution is the automation pattern (a scheduler applied to a streaming archive, producing coincidence-vetted burst events rather than raw candidates) with the QC's reliability
carried as a committed chance-coincidence rate.
\end{abstract}

\section{Introduction}
The radio-astronomy reproducibility literature increasingly ships analysis pipelines, but workflow
orchestration is easy to mis-apply. Wrapping a one-shot analysis of a static file in a scheduler like
Airflow adds a metadata database and a webserver to do what a shell script would, and exercises none of
the features (scheduling, backfill, sensors, fan-out, retries) that justify the tool. A scheduler is the
right choice when the data keep arriving. The e-Callisto network \citep{benz2009} is exactly that
case: a worldwide net of low-cost spectrometers that continuously adds 15-minute dynamic spectra from
150+ stations to a public, no-authentication HTTP archive. Maintaining a catalogue over it is an
ingestion problem: each new day must be ingested, across stations, idempotently, with the ability to
backfill history. Ingestion problems of that class are what Airflow is built for. We build that pipeline and keep the science it
performs deliberately simple (type III candidate detection), so the contribution is the automation
pattern.

\section{The pipeline}
The DAG \code{ecallisto\_ingest} has four stages,
\begin{center}
\code{wait\_for\_day} $\rightarrow$ \code{list\_stations} $\rightarrow$ \\
\code{scan\_station.expand($\cdots$)} $\rightarrow$ \code{reduce\_day},
\end{center}
each using a feature that a static pipeline does not:
\begin{itemize}
\item \textbf{Schedule and catchup.} The DAG runs \code{@daily} with \code{catchup=True}, so triggering a
date range backfills the archive one logical day per run; the twenty-year history is reachable by
backfill, not a bespoke loop.
\item \textbf{Sensor.} \code{wait\_for\_day} is a reschedule-mode sensor that pokes the day's archive
directory until it is populated, the hook for a still-filling current day.
\item \textbf{Fan-out.} \code{scan\_station} is dynamically task-mapped over the day's station
files, so each station is fetched and scanned in its own parallel task and a slow or failed station does
not block the others.
\item \textbf{Idempotent reduce.} \code{reduce\_day} writes one CSV per day, so re-running a date
overwrites rather than appends, giving safe backfills and retries.
\end{itemize}
The stack is LocalExecutor with a single Postgres metadata database on rootless Podman (no Celery or
Redis); the Fedora/Podman traps already solved for this repo's earlier pipeline (fully-qualified images,
SELinux \code{:z} bind-mount relabels, \code{AIRFLOW\_UID=0}) carry over.

\section{The worker, and why the DAG is thin}
Every task is an in-process call into \code{jansky\_research.ecallisto\_catalog}, which reuses the tested
\code{solarbursts} dynamic-spectrum tools (background subtraction, burst windowing, the per-channel ridge
detector, the robust drift fit). A spectrum is flagged a candidate when its ridge spans enough channels,
drifts the right way (frequency falling with time), and fits coherently, the discriminant validated by
the \code{solarbursts} slice. Because the DAG calls the same worker as \code{make ecallisto-day},
the scheduler adds orchestration, not a second code path: the DAG's scan task and
\code{make ecallisto-day} call the same \code{scan\_file} worker, which fetches exactly the file
the day listing named (an earlier version re-resolved files by start hour, which could analyse a
different file than listed). The worker is unit-tested offline against a synthetic observing day
whose contaminants can defeat it: alongside the injected burst and time-offset burst-shaped
interference, the fixture carries a constant narrowband carrier, a broadband zero-drift impulse, and a reverse-drift ridge, morphologies the discriminant must reject, two of them placed within
the coincidence tolerance of each other so that a morphology failure would be promoted to a
spurious event. Over \ecSynEnsN\ independent seeds the injected burst is confirmed as exactly one
event at the injected multiplicity in \ecSynEnsOk\ of \ecSynEnsN, with \ecSynEnsQuietFP\
false flags on quiet stations and \ecSynEnsContFP\ on the contaminants (drift scatter
\ecSynEnsDriftSd~MHz\,s$^{-1}$; seed-0 values in Figure~\ref{fig:ec}). CI never stands up the
Airflow stack, since it is too heavy and flaky for continuous integration, but tests the worker;
the DAG is run separately with \code{make dag-test}.

\section{Cross-station coincidence: from candidates to events}
Per-station detections are not yet a catalogue: e-Callisto stations differ in RFI environment, gain, and
sky coverage, so any single station produces spurious ridges. The physical discriminant is that a
real solar burst radiates to the whole sunlit hemisphere and is therefore recorded at the same
universal time by many stations, whereas interference is local to one. The worker's
\code{coincident\_events} clusters the day's candidate rows in peak time (single-linkage with a \ecTolS-second adjacency tolerance; note a chained cluster can span longer than the tolerance, so each confirmed event's total span is reported with it) and confirms a cluster spanning at
least \ecMinStations\ distinct stations. Two chance-coincident interference candidates are
promoted by construction, so the QC's reliability is set by the chance-coincidence rate, which is
closed-form from the per-station candidate counts and committed with every run (on the synthetic
day, \ecSynChanceEvents\ expected chance events). The sibling census slice ran its real leg at a
120-second tolerance, twice the value published here; the two papers now cross-reference the
discrepancy rather than leaving one number implied. On the synthetic day (a real type III injected at \ecSynMaxEventStations\ stations at a
common time, plus \ecSynNrfiRejected\ single-station interference events at other times), the step confirms
exactly \ecSynNevents\ event (the real burst, at \ecSynMaxEventStations\ stations) and rejects all
\ecSynNrfiRejected\ single-station candidates (Figure~\ref{fig:ec}, right). This quality-control step turns
the streaming ingest into a trustworthy burst catalogue and scales for free on the DAG's per-day
reduce. A multi-cycle occurrence census with completeness corrections is the natural next step.

\section{Discussion}
The contribution is matching the tool to the data: a scheduler for a streaming archive, with
cross-station coincidence as the quality control. Three limitations bound what that
demonstrates. Single-station detections are candidates, promoted to events only by the
coincidence step; this step is validated here on a synthetic day, and its real-data performance
depends on how many stations detect a given burst. On the one real archive day run end to end
(\ecRealSource; Figure~\ref{fig:ecreal}), the archive listed \ecRealNfilesListed\ 15-minute
spectra across \ecRealNstationsScanned\ stations; \ecRealNscanned\ were fetched and scanned
(\ecRealNfetchFailed\ fetch failures, counted rather than silently dropped) and the worker
flagged \ecRealNbursts\ candidates at \ecRealNcandStations\ stations: BIR's at 11:51:06~UT, consistent with the known 11:50~UT type III of the \code{solarbursts} slice, and OOTY's 3.2 hours earlier, so the coincidence step confirmed \ecRealNevents. The instructive
reading is that \ecRealNstationsScanned$-$\ecRealNcandStations\ stations produced no candidate
at all on a day with a known burst: the real-data bottleneck is the single-station detection
threshold, not station coverage, and until the ingest is deep enough for multi-station
detections the QC's real-data false-positive behaviour is characterised by its committed
chance-coincidence rate (\ecRealChanceEvents\ expected chance events for this day's candidate
counts). An earlier committed version of this day double-counted every listed file and analysed
a different file than labelled for most rows (the day index renders each filename twice, and
files were re-resolved by start hour); both defects are fixed, and the per-row \code{file} and
\code{t\_peak\_s} are now committed so the coincidence verdict is auditable from the
catalogue. That single day illustrates the dependence; it does not characterise it. The per-day fan-out is
capped for a bounded backfill demonstration and has not been run over all stations or all twenty
years, so a full multi-cycle occurrence census (with completeness corrections and calibration
caveats) remains the natural next step. The drift-based detector targets type III bursts; type II
(shock) detection would need a second, slower-drift template. The pattern (in-process
worker, daily schedule, catchup, sensor, dynamic-mapping fan-out, idempotent reduce, all on rootless
Podman) transfers to any frequently-updated public radio archive. Every measured quantity above is written by the
pipeline into the macros this paper \code{\textbackslash input}s; \code{make ecallisto-day
DATE=...} reproduces a day's rows without Airflow, and \code{make dag-test DATE=...} runs the same
through the scheduler.
