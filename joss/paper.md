# Summary

`jansky-research` is a tested, CPU-first Python toolkit for reproducible
radio-astronomy analyses of public survey data, with optional, opt-in GPU
acceleration for its signal-processing and machine-learning components. It is the
research sibling of the `jansky` teaching course [@jansky], composing that course's
tested helpers rather than reimplementing them. It ships more than forty
self-contained analysis "slices", each built to the same discipline — a tested tool
(pure NumPy [@harris2020]/SciPy [@virtanen2020]/Astropy [@astropy2022], with a mandatory synthetic offline
fixture) run on a real public dataset, put through an adversarial science-review
gate, and written up as a short AASTeX paper whose every quantitative result is
generated by the pipeline rather than typed by hand. The `README` carries the
authoritative slice-by-slice inventory. Exemplars by domain:

- **Fast radio bursts** — CHIME/FRB catalogue statistics [@chimecat1], the 16.35-day period of
  FRB 20180916B [@chime2020periodic], repeater timing and lensed-delay censuses;
- **Pulsars** — ATNF spectra and the $P$–$\dot P$ diagram [@manchester2005], giant-pulse and
  glitch waiting-time tests;
- **HI** — the inner Milky Way terminal-velocity curve from LAB [@kalberla2005; @reid2019],
  checked against the VGPS [@mccluregriffiths2016], and FASHI H I mass functions;
- **Solar, heliospheric and planetary** — type III beam speeds from e-Callisto, Wind and
  STEREO, Jovian and Saturnian occurrence censuses, and a blind Voyager 2 ice-giant
  rotation reanalysis;
- **Faraday, continuum and SETI** — the Galactic RM sky and, to our knowledge, the first
  RM-based dipole test (an exclusion limit), a VLASS [@lacy2020] variability census
  recovering FK Com, and a Doppler-drift injection–recovery benchmark that recovers
  Voyager 1 in public Breakthrough Listen data [@lebofsky2019];
- **GPU and machine learning** — a pure-PyTorch [@pytorch] Fast DM Transform and DSP suite
  that runs on CPU, ROCm and CUDA (bit-identically for the FDMT plane), and simulation-based
  inference [@sbi_toolkit] of a radio-emitter population.

Each module exposes the same tested entry point to the command line, the notebooks,
and the orchestrators. Orchestration is matched to the data: static-input slices
build through a server-less Snakemake [@snakemake] file-target DAG (`make figures`),
while the frequently-updated e-Callisto archive is ingested by an Apache Airflow
[@airflow] DAG on rootless Podman. `make reproduce`
regenerates the whole chain — data, analyses, papers, and arXiv packages — from a
clean checkout.

# Statement of need

Open-source radio astronomy is well served for detection and I/O, but the
*statistical analysis* of public catalogues is typically reimplemented privately for
each paper, as one-off scripts that are rarely tested, packaged, or reproducible. An amateur who wants population statistics, a rotation curve or a
periodicity search from a public dataset, with honest uncertainties, has no lightweight
library for it. `jansky-research` fills that gap with a tested toolkit aimed at three audiences: learners moving from a course to real data;
amateurs who want reproducible analyses without an observatory software stack; and
educators who need worked, citable examples that regenerate from source.

Its second contribution is methodological: a worked template for *honest*
small-scale research. Every slice is put through an adversarial science-review gate
before write-up, and the project reports negatives and limits rather than over-claiming.
Two pillars recur. The first is recover-a-known validation: each tool must recover an
injected or historically established signal (FRB 20180916B's period, the VGPS
terminal-velocity curve, the Crab's DM, FK Com's variability) before it is trusted on new
data. The second is the honest null: many slices report bounded non-detections or
systematics rather than discoveries, such as an ultra-steep-spectrum cut that is neither
pure nor complete against a reference catalogue (`spectra`), a blind Voyager 2 reanalysis
that recovers neither ice-giant period (`vgpra`), an OVRO-LWA type II census that is
false-positive dominated (`typeii`), a giant-pulse census that the detection floor leaves
unidentifiable (`pte2`), and calibrated upper limits from megaconstellation RFI trends,
repeater lensing and Stokes-V surveys (`rfitrend`, `frblens`, `wdpulsar`). The gate is not
the last word: later referee rounds have repeatedly narrowed or withdrawn claims that
passed it, and every withdrawal is recorded in the repository's `survey/` files as part of
the method.

# State of the field

The signal-processing slices sit beside established, mostly compiled codes: incoherent
dedispersion in GPU dedispersion libraries [@barsdell2012; @sclocco2016] and the Fast DM
Transform [@zackayofek2017], coherent dedispersion in `dspsr` [@vanstraten2011] and
CUDA-based tools [@bassa2017], RFI flagging with SumThreshold [@offringa2010], fast-folding
searches in `riptide` [@morello2020], and signal injection for SETI in `setigen`
[@brzycki2022]. `jansky-research` does not replace them for production use. Its kernels are
pure PyTorch, so one implementation runs on any device PyTorch supports, and each is
validated against an independent oracle. The analysis slices have no direct equivalent:
the statistics they compute are usually published as one-off scripts beside a single paper.
The toolkit's contribution there is a uniform, tested and regenerable form for that work.

# Functionality and reproducibility

The package installs with `uv`/`pip`, depends on `jansky` for shared radio-astronomy
helpers, and exposes each slice as `python -m jansky_research.<slice>` with an
`--offline` flag selecting the synthetic fixture. The core install and continuous
integration are **CPU-only**: the GPU pieces are opt-in extras (`fdmt`, `sbi`) whose
`torch` resolves from the CPU wheel index for tests, while the accelerated legs run on
ROCm locally and have been cross-checked on CUDA, with the same pure-PyTorch code and no
vendor-specific branches. Each slice is written up as an AASTeX paper under `papers/`,
twelve of them as Research Notes of the AAS submitted separately; those report individual
science results, while this paper describes the software. Headline numbers are emitted as LaTeX macros, so the papers carry no hand-typed
results. Code quality is enforced by `ruff`, `mypy`, and `pytest` with an
85% coverage floor on the synthetic fixtures, and releases follow Semantic Versioning
as codified in `VERSIONING.md`. A `pull-station-data` bridge brings the author's
rooftop-station HI spectra into the same pipeline.
